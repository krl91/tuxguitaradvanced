Version française de cette page

The Audio recognition page of Tools → Settings collects the settings of the evolved tuner and of Interactive Practice. It shows one category at a time: choose it in the Settings category list. Every setting appears exactly once, in its category. Sliders show their value and unit, updated while you move them; the recommended value is marked next to it and in the tooltip of each setting (hover over the name). The values are saved and kept after TuxGuitar closes.

Recommended values and the three ways to restore them

Every recommended value is the value used before these settings existed, so the recommended configuration behaves exactly like earlier versions. There are three different scopes:

  • Restore the recommended values of this category resets only the category shown. Takes effect with OK; Cancel discards it.
  • Restore all audio recognition settings resets every category of this page. Takes effect with OK; Cancel discards it.
  • The Defaults button at the bottom of the Settings dialog resets all TuxGuitar settings (language, style, sound, …), audio recognition included, at once, and closes the dialog.

When changes apply

  • Nothing changes before OK; Cancel keeps the previous values.
  • Tuner values: at once after OK.
  • Practice values (notes, chords, passages): at the next Start; a running practice keeps the values it started with.
  • Level and attack values: the listening restarts cleanly at once (a fraction of a second), without mixing old and new values.
  • The audio input is the exception: it changes as soon as it is chosen in the list, like in the tuner and practice windows.

Invalid or old configuration files

Values are checked when they are entered and when the configuration file is read. A value that is missing, empty, not a number, infinite or of the wrong kind is replaced by the recommended value; a number outside its range is brought to the nearest limit. An accepted pitch range smaller than the in-tune range is raised to it. Unknown entries from other versions are ignored and removed at the next save. TuxGuitar never fails to start because of this file.

Audio input

The input (device and, on multi-channel interfaces, the channel) is shared by the tuner and Interactive Practice. It is the same list as in their windows; a change applies at once and is not remembered after TuxGuitar closes. The level values decide when the signal is reported as too low, suitable, too high or clipping; practice only accepts notes at a usable level.

Practice — chords

A chord is checked against the written chord. With the recommended rule, Note names over the strum, the note names of the chord (the octave not counted) must be heard together over the strum, whatever the voicing: a chord missing two of its notes is always refused, a chord one note off may be accepted. With the rule Every string separately, each string that has overtones of its own must be heard within the strum window; strings that cannot be told apart by sound (the same note twice, or an octave of a lower string) are shown as "not checked" and never claimed as heard. Extra wrong strings are not checked in this version. Choosing a chord check level in the practice window sets the rule, the match and the attack setting; changing one of them here makes the level Custom.

Passages

The song is cut into passages in playing order (repeats and alternate endings are separate passages). At the end of a passage, if more of its notes and chords were wrong or skipped than the threshold, the passage is played again, up to the maximum. Recognition engine

This version has one pitch detection engine, FastYin (TarsosDSP). It finds one note at a time (monophonic); chords are checked with a separate spectrum analysis against the written chord (polyphonic, but only for the expected notes). "Automatic" always uses the recommended engine. No other engine is offered because none exists yet.

Limits

Recognition is based on pitch only: it cannot tell which string or fret was used. The techniques written in the score (hammer-on, pull-off, slide, bend, vibrato) are listened for, but none is verified yet: practice shows them as "cannot be checked yet" instead of guessing. Legato notes (hammer-on, pull-off, slide) have no pick attack and may have to be picked again or skipped; accepting them without an attack and rejecting extra chord strings are proposals still under review, so they are not offered as settings.

Calibrating the recognition for one input

The Input tab of the practice window shows a coloured dot next to the input chooser. Grey: no input selected. Orange: this input was never calibrated (or the default was chosen), the default settings are used. Green: calibrated, at least 60 % of the sounds of the calibration piece recognised (the recommended rate; it is an expert setting of the Advanced part, "Recognition rate kept"). Red: calibrated, but under 60 %. A sentence next to the dot warns when the noise reduction or the input gain is not what it was at the recording; the profile stays in use. A profile made at another sample rate is not applied (orange, with the reason).

Calibrate the recognition opens one window that guides you: tuning, advice, then a short piece to play once, with no tempo. The window listens by itself and counts the sounds without saying which one it heard; it stops when all were heard. You are shown the measures of the recording (sounds heard, highest level, background noise, clipping) and asked whether it is good enough. The best settings for this input are then searched on the recording, at most about two minutes, and the window blocks the application until it is done. The result shows the recognition rate with the default settings and with the settings found, for notes, chords and in total.

If the recording cannot be used, or the settings found are not better than the default, or better but under 60 %, the application never decides for you: you can record again, use the default configuration, or stop. Closing the window, at any step, asks "Stop the calibration?"; nothing is saved then. Forget the calibration deletes the profile of the selected input only, after a confirmation.

The window shows a picture of the tablature of the next sound to play: six lines (the thinnest string on top) with the fret number on the string of each note, 0 for an open string, a chord having its numbers one above the other. It changes each time a sound is heard. At the question about the quality of the recording, a check box Keep a copy of this recording for diagnosis, unticked every time, writes the recording as a WAV file in the folder tuxguitar-calibration-takes of your home folder, only when you tick it; the window shows where. The application never reads it back and never sends it anywhere.

The profile applies everywhere the recognition is used (tuner window, Follow, Arcade, Wait), except the tuner's own parameters. No audio is kept unless you tick the diagnostic copy: the recording lives in memory during the calibration and is dropped at the end or when you stop. The result is measured on one recording: confirm it by playing.

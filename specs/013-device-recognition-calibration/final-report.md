# Final report, spec 013 "per-device calibration of note and chord recognition"

Written 2026-10-16, branch `feature/interactive-practice`, local commits only (nothing pushed).

## What was built (phases 1 to 6, T001 to T044)
- **Model and store**: `DeviceKey`, `RecognitionProfile`, `RecognitionRate`, `FrontEndState`, `ProfileState`; the settings store has a default layer and an effective `get()` (default plus the active profile for 11 profile parameters); the real writers (Configuration page, `FollowSettings.setWindowMillis`) write the default layer.
- **Library** of profiles in its own module `tuxguitar-recognition-profiles` (unreadable entries skipped and kept, a failed write keeps the old profile, `remove`, listeners).
- **Scoring and search**: `SoundSegmenter`, `EventJudge` (copy of the test judge, same verdicts on the 21 notes), `CalibrationScorer` (right minus 2 per wrong acceptance against the next event), `ProfileSearch` (deterministic coordinate descent from the default, one point of gain to leave it, budget 120 s / 2000 candidates, cancel).
- **Listening mode**: `HopRecorder` (memory only), `SoundCounter`, `RecordingQuality`; `NoAudioOnDiskSourceTest` forbids any file API in the calibration code.
- **Flow, controller, window**: `CalibrationFlow` (pure table), `CalibrationController`, `CalibrationWindow` (one modal window; closing asks "Stop the calibration?"), 67 texts in English, French and Spanish.
- **Activation and dot**: `ProfileActivator` (attached in `AudioEngine.getInstance`), `EngineListeningPort`, `ProfileDot` (grey / orange / green / red, warning, Calibrate, Forget with confirmation), `CalibrationLauncher`, opt-in in `InputSelectorPanel` (Configuration page unchanged), one line in `PracticeWindow`.
- **Documentation** (T045): a new section in the three help pages, `docs/PRACTICE.md`, `README.md`, `specs/STATUS.md`.

- **T049, T050 (owner's trial, the one window)**: human tasks, open.

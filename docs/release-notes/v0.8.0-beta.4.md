## 🎸 TuxGuitarAdvanced 0.8.0-beta.4 — the Arcade view stays dark in light mode

TuxGuitarAdvanced adds **practice modes** on top of [TuxGuitar](https://www.tuxguitar.app/), the free multitrack tablature editor: it listens to your real guitar, checks the **pitch of the notes and the chords** you play against the tablature, and lets you practise note by note, in time (Follow, Arcade) or waiting for the right note.

### 🔖 About this release

A **pre-release** with one fix over 0.8.0-beta.3 (spec 021). Everything else is the same as 0.8.0-beta.3, including the score fire of spec 019.

Every feature is in all three packages (macOS, Linux and Windows), with the same behaviour. The macOS package still needs **macOS 15 Sequoia or later** and is signed with the same certificate as before.

> 🙏 **Windows and Linux users: your feedback is needed.** The author has no Windows or Linux computer at hand, so these packages are built by the CI but **have never been run**. If you try one, please say what works and what does not (launch, microphone, tuner, practice modes, Arcade) in an [issue](https://github.com/krl91/tuxguitaradvanced/issues), with your system and its version.

### 🛠️ What is fixed since 0.8.0-beta.3

* **The Arcade view keeps its dark design when your computer is in light mode.** Until now, in light mode, the scene was laid over the light background of the window: the whole view came out washed out, with dark fret wires on a pale neck. It now paints its own dark background, so it looks the same in light and in dark mode, on macOS, Linux and Windows.
* The other windows (the practice window, the Arcade results, the buttons under the Arcade view, TuxGuitar itself) keep following your system's light or dark mode, as before.
* In dark mode the Arcade view may look very slightly darker than before: it now uses exactly the background of its design.

### ✅ What was checked, and by whom

* **Tests on the author's Mac (dark mode):** the full macOS build is green: 1,371 practice tests and 378 audio-engine tests, 0 failures. A new test on the real SWT toolkit paints Arcade frames and checks every empty pixel: it failed before the fix (the system's grey showed through) and passes after it, on both painting paths, after a resize and before the first note. All 45 tests on the real toolkit pass.
* **On GitHub's macOS 15 machine, which is in light mode:** the tests on the real toolkit show the dark background there too, and the check that each note lands between its painted frets, which failed in light mode, now passes. One check that counts the flames of the stage still fails on that machine: it is slower, so Arcade lowers its picture quality during the check, as designed. The same check passes on the author's Mac.
* **Not checked by anyone yet:** the Arcade view in light mode in a real practice run (for the author to check); the **Windows and Linux packages were never run** (built only).

### 🚧 What is **not** fixed

* Notes and chords whose **attack is not heard** (a soft note, a low input level) are still refused.
* A chord with **one string missing** can still be accepted.
* *Reduce motion* is read from the system on macOS only; on Windows and Linux the fire always moves.
* The macOS package is **not notarised**: the first launch needs *Open Anyway* (System Settings → Privacy & Security). The Windows package needs Java 17 or later.

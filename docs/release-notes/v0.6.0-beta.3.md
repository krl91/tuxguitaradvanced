## 🎸 TuxGuitarAdvanced 0.6.0-beta.3 — the macOS app should now open (a trial)

TuxGuitarAdvanced adds **practice modes** on top of [TuxGuitar](https://www.tuxguitar.app/), the free multitrack tablature editor: it listens to your real guitar, checks the **pitch of the notes and the chords** you play against the tablature, and lets you practise note by note, in time (Follow, Arcade) or waiting for the right note.

### 🔖 About this beta

The application is **the same as 0.6.0-beta.2**. What changes is **how the macOS package is built**: with the earlier releases, a macOS that checks downloaded apps strictly answered *« TuxGuitarAdvanced est endommagé et ne peut pas être ouvert »* (*is damaged*), with no way to open it.

* **The cause:** the app put its Java runtime, jars and resources in `Contents/MacOS`, where macOS accepts only executables, so the signature of the app did not verify (this was already so in every release since 0.5.0).
* **The change:** the application now lives in `Contents/Resources/tuxguitar`, the launcher starts it from there, and the **whole app is signed** (with the project's self-signed certificate). The Release workflow checks that the signature is valid before it attaches the zip.
* **What you should see now:** the usual macOS message *« Apple n'a pas pu confirmer que … ne contenait pas de logiciel malveillant »*, then **System Settings → Privacy & Security → Open Anyway**, as for other open-source apps that are not notarised. If you still see *damaged*, tell us, and as a workaround run `xattr -cr TuxGuitarAdvanced.app` once.

### ✅ What was checked, and by whom

* On the author's Mac, a local build with the same change: the signature of the app verifies, the launcher starts the application from its new place, and a copy marked as downloaded gets the normal « could not verify » message instead of *damaged*.
* **Not tried yet by anyone: the zip downloaded from this release opening on a Mac.** That is what this beta is for: please try it and tell us what macOS says.
* Windows and Linux packages are unchanged by this fix (they were built and read by the version verifier in beta.2).
* The version and the commit are shown as in 0.6.0-beta.2 (About, title, `--version`, every package).

### 🚧 What is **not** fixed

* The macOS package is **not notarised** (no Apple Developer ID): the first launch needs *Open Anyway*. The self-made certificate gives a valid signature, not Apple's approval.
* A chord with **one string missing** can still be accepted: nothing here changes the recognition algorithms.
* The practice modes exist only in the macOS, Linux and Windows **SWT** packages; the Windows package needs Java 17 or later.

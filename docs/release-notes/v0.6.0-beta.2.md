## 🎸 TuxGuitarAdvanced 0.6.0-beta.2 — the same version and commit everywhere

TuxGuitarAdvanced adds **practice modes** on top of [TuxGuitar](https://www.tuxguitar.app/), the free multitrack tablature editor: it listens to your real guitar, checks the **pitch of the notes and the chords** you play against the tablature, and lets you practise note by note, in time (Follow, Arcade) or waiting for the right note.

### 🔖 About this beta

The practice modes, Arcade and its five levels are **the same as in 0.6.0-beta.1**. What changes is that **every build now says which release it is and which commit it was built from**, in the same way everywhere. Before, About showed the upstream number (2.1.1) and the packages said `9.99-SNAPSHOT`.

### ✨ What is new

* **About** shows `TuxGuitarAdvanced 0.6.0-beta.2`, the short commit under it and the full commit in the description tab, with a **Copy the version** button that puts `TuxGuitarAdvanced 0.6.0-beta.2 (<full commit>)` on the clipboard, ready to paste into a bug report (the copy works with the SWT builds, i.e. the three packages of this release).
* The **title of the main window** is `TuxGuitarAdvanced 0.6.0-beta.2 - <file>` by default (a title you wrote yourself in the settings is kept as you wrote it). `tuxguitar.sh --version` and the `${appversion}` variable give the same version.
* **Every package carries it**: `share/build-info.properties` in all of them, the macOS `Info.plist`, the version resource of the Windows `tuxguitar.exe`, the Debian package version (`0.6.0~beta.2`), the file names and this release page. A local build says `dev` instead of a release number.
* **A release is checked before it is published**: the Release workflow reads the version and the commit in every package and in the draft release, and does not publish if one differs. A tag may now carry any label; a tag with a label is published as a pre-release.
* The version stamped in `.tg` files is unchanged. How it works: `docs/VERSIONING.md`.

### ✅ What was checked, and by whom

* **Tests:** the full macOS build is green (1,172 practice tests, 373 audio-engine tests, 0 failures); the new scripts have their own self-tests.
* **macOS:** a build made with a release version was read by the verifier (9 places in the app, 10 in the zip named like a release) and prints the right `--version`.
* **Not seen by anyone yet:** the **About window, the title and the Copy button on screen** (the wiring and the clipboard are tested, the layout was not looked at); a `.tg` file saved by this build.
* **First run of the release checks:** the Windows and Linux builds of the version resource, the Debian version and the release workflow's own checks **had never run before this release**. If one of them failed, this release would not exist; if you read this page, they passed on their first run, and the packages were read by the verifier.

### 🚧 What is **not** fixed

* A chord with **one string missing** can still be accepted: nothing here changes the recognition algorithms.
* The practice modes exist only in the macOS, Linux and Windows **SWT** packages.
* The macOS package is signed with a self-made certificate and not notarised (the first launch needs *Open Anyway*); the Windows package needs Java 17 or later.
